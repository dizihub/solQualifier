User guide

How the application works

  1. Open the Projects tab lists every solution assessment recorded.
  2. Select + Add New Solution for new Solution Assessment.
  3. Complete the solution-profile fields (including the Code Repository Path) and answer every question with Yes, Partly or No and the Save it.
  4. Saved solution appears in the project list with empty Result. At this state, one can Edit the record or select Run assessment to classify it.
  5. Once a result exists, Edit and Run are disabled for that Solution row.

    6. Use these definitions as the interpretation guide when answering the assessment.

    Proof of Concept (PoC)

    Definition: A controlled experiment created to determine whether a technical, engineering, data, or business hypothesis is feasible.

    Primary Question: Can this idea work?

    • Specific hypothesis documented
    • Success criteria measurable
    • Representative scenarios tested
    • Results and limitations captured
    • No production SLA commitment

    Minimum Viable Product (MVP)

    Definition: The smallest complete solution delivering measurable value to real users.

    Primary Question: Does it provide sufficient business value?

    • Bounded end-to-end workflow
    • Real users included
    • Real-world data used
    • Basic security and operations
    • Value measured through KPIs

    Enterprise Grade

    Definition: A production-ready, secure, scalable, governed, and supportable solution.

    Primary Question: Can the enterprise safely depend on it?

    • Production approved
    • Scalable and resilient
    • Security and compliance validated
    • Monitoring operational
    • L1/L2/L3 support defined
    Dimension PoC MVP Enterprise Grade
    Core Purpose Prove Feasibility Prove Value & Adoption Prove trust, scale, and sustained operation
    Users Developers, SMEs, evaluators Named Pilot Users Production User population
    Data Sample, synthetic, anonymised, or limited Representative real-world data Governed Production Data
    Environment Lab, sandbox, developer, or temporary setup UAT, pilot, staging, or limited production-like setup Approved production environment
    Operations No production operations commitment Basic monitoring and support ownership Full service model, runbooks, SLAs/SLOs, change and incident processes
    Decision output Proceed, pause, stop, or redesign Scale, pivot, commercialise, or stop Operate, expand, optimise, and govern lifecycle

    Decision rules

    ClassMandatory rule
    PoCFeasibility evidence exists, but one or more MVP gates are not passed.
    MVPAll MVP gates pass: bounded workflow, real users, representative data, measured value and controlled operation.
    Enterprise GradeAll MVP gates pass, all critical enterprise controls are Yes, every enterprise control is at least Partly, and enterprise readiness is at least 85%.
    Mandatory maturity gates override the average score.
    Scoring Logic

    The classifier is a deterministic, rule-based engine. The same answers always produce the same class, and mandatory gates always override raw averages.

    1 · How each answer is scored

    AnswerValueCounts as…
    Yes1.0passes strict gates and coverage
    Partly0.5counts for coverage, but not strict "Yes" gates
    No0.0fails gates and coverage

    2 · Section scores

    • Questions are grouped into A – Feasibility, B – MVP viability and C – Enterprise readiness.
    • Each section score = average of its answer values × 100, giving a PoC %, MVP % and Enterprise %.

    3 · Mandatory gates

    • PoC gate — every Section A item is at least Partly and PoC % ≥ 63%.
    • MVP gates — five bundled gates (bounded end-to-end workflow, real users + usability, representative governed data, measured business value, controlled operation). Each bundle requires all its questions to be Yes, and all five bundles must pass.
    • Enterprise gates — MVP passes, and all 7 critical controls are Yes, and every Section C item is at least Partly, and Enterprise % ≥ 85%.

    4 · Final classification (evaluated top-down)

    • Enterprise-Grade → if all enterprise gates are met.
    • MVP → else if all MVP gates pass.
    • PoC → else if the PoC gate passes.
    • Pre-PoC / Concept → if none pass.
    Key principle: the model is tiered — each level requires the level below it plus stricter controls — and gates beat averages, so a high average can never promote a solution whose mandatory gate has failed.
